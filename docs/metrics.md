# 검증 지표 기록

PLAN.md 4장 가설(첫 판 완료율, 재방문율)을 운영 DB에서 매주 집계해 이 파일 끝에 붙인다.
기록은 **집계값만** 남긴다. 회원 ID·아이디·닉네임·토스 키는 어디에도 쓰지 않는다.

## 기록 방법

```bash
bash deploy/metrics.sh          # 운영 DB에서 집계해 이 파일 끝에 붙인다 → 확인 후 커밋
bash deploy/metrics.sh --print  # 붙이지 않고 출력만
```

- 운영 서버 컨테이너 안에서 `node server/src/metrics.ts --markdown --since <기준 시각>` 을 실행한다.
- 각 미션 단계를 시작할 때 실행한다. 직전 기록 뒤 7일이 넘었으면 다른 일보다 먼저 기록한다 (CLAUDE.md 운영 절).
- 기준 시각 뒤에 생긴 회사 테스트 계정은 로컬 `deploy/.env` 의 `METRICS_EXCLUDE_USER_IDS`(쉼표 구분)에 넣는다. 값은 실행할 때만 `docker compose exec -e` 로 컨테이너에 넘어가고, 기록에는 제외 인원수만 남는다.

## 정의

- **채널**: 토스 익명 키로 가입한 회원(users.toss_key 있음)은 `toss`, 그 밖은 `web`.
  아이디 접두 `toss_` 로 나누지 않는다. 웹 가입 아이디 규칙(`USERNAME_RE = /^[a-zA-Z0-9_]{4,20}$/`)이 `toss_...` 를 허용해 겹치기 때문이다.
- **제외**: 집계 기준 시각(`--since`, 기본은 deploy/metrics.sh 의 `LAUNCH_SINCE`) 이전 가입자 전부 + `METRICS_EXCLUDE_USER_IDS`. 기록마다 "제외한 회원 수 N명, 기준 ○○" 을 찍는다.
- **가입 주 코호트**: 가입 시각을 한국 시간 주(월요일 0시 시작)로 묶는다.
- **가입 후 7일 안 첫 판 완료율** (코호트 표): 분모 = 가입 후 7×24시간 안에 판을 시작한 회원, 분자 = 그중 같은 기간에 한 판을 끝까지 마친 회원. 코호트의 누군가가 아직 가입 후 7일이 지나지 않았으면 '미성숙'을 붙인다.
- **누적 첫 판 완료율** (채널별 요약): 판을 시작해 본 회원 중 언제든 한 판이라도 마친 비율. 코호트 표와 기간이 달라 따로 적는다.
- **재방문**: 가입한 한국 날짜의 **다음 날 0시부터** N일 안에 `visit` 또는 `round_start` 이벤트가 있으면 재방문으로 센다. `round_finish` 는 세지 않는다(전날 시작한 판을 자정 넘어 끝낸 것까지 재방문으로 잡히는 것을 막음).
  - D1 재방문율: 가입 다음 날 하루. 7일 재방문율: 가입 다음 날부터 7일.
  - 판정 기간이 끝난 회원만 분모에 넣는다. 코호트 전원이 판정 기간을 끝내기 전이면 '미성숙'(판정 가능한 인원과 비율을 괄호로 함께 적음).
- **visit 이벤트**: 회원별 한국 날짜 하루 1회. `/api/auth/me`(앱을 열 때 호출), `/api/auth/login`(웹 로그인), `/api/auth/toss`(토스 로그인, 기존 회원 재로그인 포함)에서 기록한다.
  - **visit 보강 배포일: 2026-10-12** (T0112). 그 전에는 `/api/auth/me` 에서만 기록했다. 집계 기준 시각은 이 배포일 0시(2026-10-12 00:00 KST)로 둔다. 배포 시각(15:23 KST)이 아니라 0시로 둔 이유: 그날 생긴 토스 가입자를 버리지 않기 위해서이고, 앱을 열 때 호출되는 `/api/auth/me` 가 그 전에도 visit 를 남겨 재방문 판정에 큰 차이가 없다.
  - 2026-10-12 가입자에는 토스 심사·테스트 계정이 섞여 있을 수 있다. 서버에는 이를 구분할 표시가 없으므로, 알게 되면 `METRICS_EXCLUDE_USER_IDS` 에 넣는다.
- **표본 기준 30명 [가정]**: 코호트 가입자가 30명 미만이면 '표본 부족'으로 표시하고 가설 판정을 보류한다. 30명은 통계 근거가 아니라 비율이 한두 명에 크게 흔들리지 않게 잡은 운영상 가정이다. 데이터가 쌓이면 다시 정한다.
- **지난 7일**: 집계 시각 직전 7×24시간의 가입자 수, 활성 사용자(아무 이벤트나 남긴 회원) 수, 완료한 판 수.

## 외부 지표 (앱인토스 콘솔)

조사일 2026-10-12. 출처: 앱인토스 개발자 문서 [핵심 지표](https://developers-apps-in-toss.toss.im/guide/analytics/conversion-metrics), [llms-full.txt](https://developers-apps-in-toss.toss.im/llms-full.txt) (`# 핵심 지표`, `# 로그(이벤트) 가이드`, `# Analytics.log`, `# 토스 로그인 마이그레이션` 절).

- 콘솔 → 미니앱 → 왼쪽 메뉴 '핵심 지표'에서 **활성 지표 1개**와 **전환 지표 최대 3개**(대표 전환 1개)를 등록한다. 토스는 이 지표로 비슷한 사용자를 찾아 노출·추천한다. 변경은 다음 날부터 적용된다.
- 전환 지표는 **템플릿 선택** 또는 **커스텀 이벤트 직접 조합(OR 조건, 파라미터 포함)** 으로 등록한다. 원하는 것이 없으면 '원하는 지표가 없어요'로 토스팀에 요청할 수 있다.
- 전환 지표 템플릿 11종(공식 문서 표 그대로): 수익 발생한 유저, 토스페이 결제한 유저, 인앱 상품 구매한 유저, 인앱 광고 시청한 유저, 한 명당 평균 매출(ARPU), 한 건당 평균 결제 금액(AOV), **토스로그인 완료한 유저**, **유저 식별키 발급받은 유저**("별도 서버 없이 유저 식별키를 발급받은 사용자"), **게임 플레이 완료한 유저**("게임을 1회 이상 완료한 사용자"), 알림 받기 동의한 유저, 특정 경로로 들어온 유저. 앞의 6종만 매출 기반이다.
- **'게임 플레이 완료한 유저'** 는 '한 판 끝내기'와 뜻이 가장 가깝다. 확인한 것과 못 한 것:
  - 블라인드캔들은 앱인토스에 **비게임** 미니앱(appName=blindcandle)으로 등록돼 있다(회사 기억 blindcandle.md, 2026-10-08 인수 기록).
  - 공식 문서는 '게임'과 '비게임'을 나눠 API를 제한한다. 예: 게임 전용 `getUserKeyForGame` 은 비게임 앱에서 `INVALID_CATEGORY` 를 돌려준다(llms-full.txt `# 토스 로그인 마이그레이션` 절). 게임 SDK(Game 도메인)는 게임센터 리더보드·게임 프로필·점수 등록만 제공한다(llms-full.txt SDK 목록).
  - 이 템플릿이 **비게임 앱에서도 선택 가능한지**, **어떤 신호(SDK 호출, 게임센터 점수 등록 등)로 '게임 완료'를 세는지는 공식 문서에 적혀 있지 않다 → 확인 못함.** 콘솔 '핵심 지표' 화면에서만 확인할 수 있다. 게임 전용 API로 미루어 비게임 앱인 우리에게는 쓸 수 없거나 집계되지 않을 가능성이 높다고 본다[추정].
- **SDK 호출 없이 바로 쓸 수 있는 템플릿**: '유저 식별키 발급받은 유저'. 미니앱은 이미 앱을 열 때 `User.getAnonymousKey()` 로 식별키를 발급받으므로(web/src/miniapp.ts) 사실상 '앱을 연 사용자' 수다. 활성·유입 확인용이지 '한 판 완료' 전환은 아니다. '토스로그인 완료한 유저'는 우리가 토스 로그인(appLogin)을 쓰지 않아 해당 없음.
- 결론: '한 판 완료'를 콘솔 전환 지표로 보려면 **(가) '게임 플레이 완료한 유저' 템플릿이 비게임 앱에 열려 있고 별도 연동 없이 집계되는지 콘솔에서 확인**하거나(확인 못함, 사용자가 콘솔에서 볼 수 있음), 안 되면 **(나) 커스텀 이벤트로 조합**해야 하고 이것은 **SDK 호출이 필요하다**: `@apps-in-toss/web-framework` 의 `Analytics.click / impression / screen / log`(SDK 0.0.26 이상, 토스앱 5.208.0 이상). 페이지 이동 로그만 자동 기록된다. 샌드박스·출시 전 데이터는 집계되지 않고 출시 다음 날부터 보인다.
- **2026-10-12(T0131)부터 미니앱 코드가 커스텀 이벤트를 남긴다** (`web/src/analytics.ts` 의 `logEvent`, `Analytics.log({ log_type: 'event' })`). 이 버전 .ait 가 검토·승인·출시된 다음 날부터 콘솔에 보인다. 그 전까지는 이 파일의 서버 집계가 유일한 기준이다. 아래 '앱인토스 커스텀 이벤트' 절 참고.

### 앱인토스 커스텀 이벤트 (T0131)

이벤트 이름은 snake_case 로 **고정**한다. 바꾸면 콘솔 지표 등록을 다시 해야 한다. 서버 이벤트(`server/src/app.ts` 의 `store.logEvent`)와 이름·시점을 맞췄다.

| 이벤트 | 남기는 시점 | 서버 지표와의 관계 | params |
|---|---|---|---|
| `round_start` | `Game.createRound()` 에서 서버가 라운드를 만든 직후(`POST /api/rounds` 성공) roundId당 1회. 일시정지 해제(`start()`·`togglePlay()`), 재로그인 이어하기(`resume()`)에서는 남기지 않는다 | 서버 `round_start` 도 `POST /api/rounds` 성공 때 기록한다(같은 정의) | `leverage` |
| `round_finish` | `Game.finish()` 에서 `api.finishRound` 응답이 `saved === true` 일 때 1회. 저장 안 됨(캔들 0개)·요청 실패면 남기지 않는다 | 서버 `round_finish` 도 `saved` 일 때만 기록한다(같은 정의) | `leverage`, `outcome`, `trade_count` |

- **params 허용 목록** (`ALLOWED_PARAM_KEYS`, 이 밖의 키는 보내기 전에 버린다):
  - `leverage`: 숫자. 그 판의 레버리지 배수.
  - `outcome`: `profit` / `loss` / `liquidated` / `flat` 중 하나. 청산이 한 번이라도 있으면 `liquidated`, 아니면 최종 평가금이 시작 자금보다 크면 `profit`, 작으면 `loss`, 같으면 `flat`.
  - `trade_count`: 숫자. 그 판에서 끝난 거래 수.
- **금지 (params 에 절대 넣지 않음)**:
  - 종목명·심볼·마켓(coin/주식 등)
  - 가격·시각·캔들 값 (시세 원본 내보내기 금지, PLAN.md 10장)
  - 닉네임·아이디·회원 ID·toss_key (`anonymous_key` 는 SDK가 자동으로 붙이므로 직접 넣지 않는다)
  - 손익 금액·수익률·평가금
- 일반 웹 빌드에서는 SDK를 불러오지 않고 바로 돌아간다(`MINIAPP` 거짓). 미니앱에서도 결과를 기다리지 않고 오류를 삼켜 게임 진행에 영향이 없다. 테스트: `web/src/analytics.test.ts`, `web/src/game/game.test.ts` '앱인토스 측정 이벤트'.
- **콘솔 등록 방법** (콘솔 → 미니앱 → '핵심 지표'):
  1. 활성 지표(1개, 재방문 기준): 템플릿 3종 중 '한 판 시작/완료'에 가장 가까운 것을 고른다. 맞는 것이 없으면 출시 다음 날 이후 '직접 조합하기'로 `round_start` 를 고른다.
  2. 전환 지표: 대표 전환 **'한 판 완료' = `round_finish`**. 출시 다음 날 이후 '분석 > 이벤트'에 `round_finish` 가 보이면 '직접 조합하기'에서 이벤트 `round_finish` 를 골라 등록하고 대표 전환으로 지정한다. 필요하면 파라미터 조건(예: `outcome`)을 더할 수 있다. '게임 플레이 완료한 유저' 템플릿이 비게임 앱에서 선택·집계되는지는 위 항목대로 확인 못함.
  3. 변경한 지표는 다음 날부터 적용된다.
- **주의: 콘솔 값이 운영 DB보다 낮게 나온다.** 토스앱 5.208.0 미만에서는 `Analytics.log` 가 에러 없이 조용히 무시되고, https 가 아니거나 샌드박스면 전송되지 않는다. 그래서 콘솔 전환율·활성 사용자는 이 파일의 서버 집계보다 작게 나온다. 두 값을 비교할 때 이 차이를 감안하고, 가설 판정은 서버 집계로 한다(콘솔은 토스 노출 평가 참고용).
