# 미션 헌장: 블라인드캔들(코인 선물 트레이딩 연습) 운영·성장

## 방향
2026-10-12 앱인토스에 출시한 블라인드캔들 미니앱(표시명 '코인 선물 트레이딩 연습', appName blindcandle, 작업 공간 blindcandle, 웹 blindcandle.com)을 사용자 개입 없이 회사가 자율 운영하며 키운다. 사용자 지시(2026-10-12): "앞으로 내 개입 없이 너희가 자율적으로 발전시켜나가라."
기준 문서: 작업 공간 PLAN.md(가설·판단 기준 4장), CLAUDE.md(운영 규칙), 회사 기억 blindcandle.md.

## 원칙
- 판단은 수치로 한다. PLAN.md 4장 가설을 순서대로 검증한다: 첫 판 완료율 50%↑ → 7일 재방문율 20%↑ → 무료 한도 도달 15%↑ → 결제 5%↑. 미달이면 원인을 찾고 한 가지만 바꿔 1주 더 돌린다. 2번 연속 미달이면 타깃·사용사례를 다시 정한다.
- 첫 단계는 측정부터: 운영 DB·서버 로그로 위 지표를 뽑는 방법을 확인·구현하고 첫 수치를 기록한다. 지표 없이 기능을 늘리지 않는다.
- 2026-10-22부터 앱인토스 노출은 출시→추천→부스팅 단계로 나뉘고 재방문율·전환율로 정해진다(https://toss.im/apps-in-toss/blog/mini-app-exposure-faq). 재방문을 1순위로 둔다.
- 정체성은 '차트 기반 코인 선물 매매 연습'(롱/숏·레버리지·청산·차트 읽기). 장기·포트폴리오형 모의투자, 주식은 하지 않는다.
- 반드시 지킬 것(PLAN.md 10장): 현금·코인·토스포인트 경품 없음, 종목 추천·매매 신호·수익 보장·레퍼럴 없음, 시세 원본 내보내기 없음. 운영 점검 조건(뒤로가기 중복 금지, 뒤로가기·닫기 작동, 테스트 광고 키 금지) 유지.
- 운영 안정성: 매 단계 blindcandle.com 응답, POST /api/auth/toss(400이면 정상)를 확인하고 장애는 최우선으로 고친다.
- 사용량 절약: 한 단계에 dev 업무 1~2건. 기능 개선은 .ait 재빌드·콘솔 업로드·재심사가 필요하므로 묶어서 낸다.
- 사실과 추정을 구분하고, 앱인토스 정책은 공식 문서로 확인한 것만 사실로 쓴다. 레퍼런스(유사 앱·공식 문서) 2~3개 이상을 plan.md에 남긴다.

## 결재·사용자 업무
2026-10-12 사용자 지시(T0097, "다 자율적으로 하란 말이야")로 회사는 자율 운영(config autonomy: true)이다. git push·운영 배포·비용·외부 공개는 `bf approval request`로 이력에 남기면 자동 승인되며 회사가 직접 진행한다(무엇을·왜·위험·되돌리는 법을 적는다). 사람만 할 수 있는 일(앱인토스 콘솔 .ait 업로드·검토 요청, 사업자등록·결제 수단 등)만 사용자 업무로 남기고, 단계마다 최대 1회로 묶는다. 콘솔 업로드를 자동화할 공식 수단이 확인되면 그쪽으로 옮긴다.
